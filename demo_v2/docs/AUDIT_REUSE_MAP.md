# DEMO V2 — Audit & Reuse Map

Source audit: 2026-10-29, `dviry75/polymarket-collector`, clean isolated checkout of `main` at `d26dda4ec78d9c567f1fcfe98a99c80cc887733c`. The user supplied GitHub as the source; this is not the server working tree. Runtime/service health and deployed-code identity were not verified. Root `CURRENT_STATE.md` is absent in this revision. Product authority: [SOURCE_OF_TRUTH.md](SOURCE_OF_TRUTH.md), then [DECISIONS.md](DECISIONS.md).

Source paths below are relative to `polymarket-collector/` unless marked repo-root. Line numbers refer to the audited revision. This audit creates documentation only; no application imports, tests, migrations, production DB access, service operations, or trading requests were executed.

## Executive Summary

- Recommend **Option C + a narrow Option A**: isolated DEMO V2 domain/runtime/persistence, directly importing proven pure helpers. Defer Option B until separately authorized; extracting shared code now would change LIVE.
- Direct reuse is justified for `live/order_book.py` and `live/strategy.py::exact_trigger`: their dependency closure is standard-library-only and contains no credentials, DB connection, adapter or runtime initialization.
- Adapt public discovery, WS transport, rollover and official resolution orchestration. Their present implementations depend on `LiveRepository`, LIVE state names and/or BTC 5m timing; public network access does not make the whole module generic.
- Existing Paper Trading is a useful simulation reference, not a compatible backend: it shares LIVE tables, restricts concurrency, uses side quotas/USD sizing, and prefers depth VWAP for exits.
- **Main research-integrity risk:** Paper Trading receives a sampled/coalesced persistence stream. Exact entry or TP/SL observations can disappear before evaluation. Use ordered actionable observations independently of lossy telemetry, with generation/freshness checks and no replay across gaps.
- Existing fee provenance is valuable, but no inspected path supplies the complete V2 gross-share → buy-fee/net-share → exit/settlement → wallet-ledger model. Missing required fee evidence must block entry, not become a default rate or zero.
- Keep all sessions, financial state, recovery gates and resources DEMO-owned. Reuse credential validation logic through a credential-only boundary; do not reuse LIVE cookies, signing secret, session-version state or trading env.
- Existing tests supply strong fixtures and failure scenarios, but several assert explicitly incompatible behavior. Reuse assertions selectively and add the V2 validation matrix in future implementation; no frontend work belongs here.

## Existing Code Conflicts With DEMO V2

1. **Market identity/timing:** discovery uses fixed BTC prefixes and current/next `300`-second slots (`market_discovery.py:12,42`); subscription selects only current BTC (`repository.py:714`); resolution queue parses BTC slug+300 (`repository.py:769`). V2 needs 21 catalog definitions, verified metadata times and monitoring of held older instances. Legacy exits select every open deal without event/token filtering (`app.py:2634`), so current-instance quotes can be applied to an older deal.
2. **Frequency/concurrency/re-arm:** legacy `has_open_deal` plus `idx_deals_one_open_per_rule` (`app.py:2526,825`), paper side quotas/global rule gate (`paper_trading.py:163–178`) and unique rule+event open index (`repository.py:458`) conflict with shared frequency and concurrent positions. LIVE locks by event alone (`strategy_repository.py:72,2172`), coupling independent rules. Paper deduplicates samples, not leave-and-return edges. Adapt the LIVE edge-state idea (`strategy_runtime.py:850–930`) to rule+instance/side observations and shared counters.
3. **Trigger stream/no-backfill:** legacy polls REST every two seconds (`app.py:69,2990`); paper consumes throttled/coalesced `on_snapshot` (`market_websocket.py:2535,2624,2631`). Neither proves every exact edge is observed. An up-to-date local `received_at` is not exchange freshness (`paper_trading.py:259`). Across reconnect/recovery, discard old queued decisions; only new valid observations may act. LIVE account-trade history ingestion/backfill (`live/trade_window.py`, `reconciliation.py`) must never reconstruct simulated entries/exits; verified resolution remains allowed.
4. **Entry gates not specified by V2:** legacy validation rejects entry `0.5`, requires both TP/SL and gates new rules until next event (`app.py:1099,1163`). Both legacy and paper skip simultaneous-side matches (`app.py:2734`, `paper_trading.py:154`); LIVE may lock the event as skipped. Do not carry these over as requirements. LIVE immutable prices, 120-second window, fixed schedule/exposure and single entry slot (`strategy.py:30,145`, `strategy_runtime.py:228,1547`) are reference only.
5. **Exit price/lifecycle:** legacy stores configured thresholds and classifies by exit reason (`app.py:2628`), rather than observed bid and closed net P&L. Paper uses observed bid or depth VWAP (`paper_trading.py:272`); V2 requires the observed bid, including jumps. Both legacy and paper joins read current-rule TP/SL (`app.py:2634`, `repository.py:981`), despite paper retaining entry JSON. V2 exits must use the immutable entry version and continue after edits/disable/archive.
6. **Resolution:** WS normalizer invents bid/ask payouts and paper sends them through its exit-fill method (`market_websocket.py:2655`, `paper_trading.py:68`). The REST resolver only updates market metadata; V2 additionally needs an idempotent position+ledger settlement with no synthetic order-book sell, no sell fee and no redemption dependency.
7. **Fees/shares/wallet:** legacy/paper size as USD/price, default rate to `0.07`, preserve gross shares and subtract cash fees (`app.py:1449`, `repository.py:1047,1096`). LIVE `fee_amount` floors to six decimal places (`strategy.py:189`); legacy rounds to five (`app.py:1375`). Fee evidence resolver may infer zero from incomplete evidence and does not use the discovered exponent (`fee_accounting.py:46,79`). None can be promoted to V2 fee authority unchanged. Preserve current applicable fee rules and buy share deductions; missing evidence blocks entry. LIVE account equity/caps do not define the V2 wallet.
8. **Freshness/recovery scope:** `OrderBookSet.event_ready` deliberately does not expire an idle ready book (`order_book.py:349`), while `EntryReleaseEvaluator` separately checks book age (`pause_recovery.py:199`). A ready book flag or socket alone is insufficient. Port coherent DEMO freshness/stability rules without importing LIVE User WS, reconciliation, canary, kill/pause or manual financial-repair requirements. Add required-fee/underlying/discovery/DB/worker health.
9. **History/schema/API:** legacy results allow only open/win/loss (`app.py:677`) and initialization backfills history (`app.py:850`). LIVE/paper financial columns often use REAL; V2 needs decimal-safe money, reproducible gross/net share accounting, immutable rule versions, underlying observations and ledger-based aligned filters/KPIs, including break-even. Do not inherit archive/prune jobs or historical cutover filtering.
10. **Underlying/auth:** BTC volume samples are not underlying open/entry/exit price observations (`app.py:2248`). LIVE cookie/session version/secret are not DEMO sessions (`auth.py:20,70`, `dashboard_app.py:38`). Same credentials do not authorize shared session or LIVE DB access.

## Proposed DEMO V2 Boundary

**Option C + A now; Option B only after a separate impact-reviewed task.** Keep DEMO configuration, entrypoint, public-data orchestration, discovery catalog, demand subscriptions, per-rule engine, immutable versions, positions, fee policy, underlying feeds, ledger, migrations, health/recovery, auth/session, read models/APIs and tests under `demo_v2/`. Keep dedicated DB/service/env/log/runtime/route ownership. No frontend. No existing code extraction or LIVE edits are part of Phase 0.

Allow direct imports only of `live.order_book` and `live.strategy.exact_trigger`, whose imports were inspected and do not initialize LIVE. Give these dependencies explicit import/behavior regression coverage later. Adapt WS and REST resolver code under `demo_v2/` with injected public clients, DEMO repository interfaces and DEMO-only diagnostic paths; do not satisfy their dependencies by instantiating `LiveRepository` or `StrategyRepository` against LIVE. Preserve proven book algorithms rather than rewriting them.

Separate a lossless ordered decision path from bounded/lossy raw telemetry. Persist decision provenance and atomically commit position, counter and wallet effects; reconnect/restart requires fresh generation data and forbids missed-event reconstruction. Official resolution can still settle persisted open positions. Credential-only provisioning may supply the same username/password hash to a DEMO validator, but its session secret/cookie/revocation state stay independent. Never import/configure LIVE routers, app entrypoints, trading adapters, reconciliation, IPC command handlers or production env loaders in DEMO execution.

## Recommended Build Order

1. Approve the isolated package/resource boundaries and narrow import allowlist; define public provider contracts and dependency-isolation checks.
2. Design DEMO-only schema for catalog/instances, rules+versions, counters/re-arm provenance, positions, fees, underlying observations, incidents and wallet ledger; specify atomicity/restart invariants.
3. Adapt discovery/WS/rollover/resolution evidence for all market families, demand subscriptions and ordered fresh observations; test resync/overflow/no-backfill with fake feeds.
4. Establish applicable fee/reference-price providers and per-market readiness; validate net-share arithmetic, precision and provenance before permitting entry.
5. Implement rule scheduling/windows/filters, exact triggers/re-arm/shared frequency and concurrent positions using immutable entry versions.
6. Add observed-bid TP/SL and official 1/0 settlement with atomic, idempotent ledger/P&L and global/per-rule/filter-aligned KPI projections.
7. Wire DEMO health/stable recovery and separate authentication/session; expose the documented JSON APIs and explicitly confirmed DEMO-only resets.
8. Complete isolated V2 validation-matrix/integration tests and deployment preparation. Actual deploy/service operations require a later authorized task.
